14 · Checkpoint、Thread 与崩溃恢复

存档保存状态，不保存 Python 暂停的调用栈。

原理与边界

Checkpointer 在执行边界保存图状态，使同一个 thread 可以继续任务、检查历史或从旧状态分支。thread_id 是逻辑存档归属，不是操作系统线程。InMemorySaver 便于演示但进程退出就丢失；真正抗重启需要持久后端、正确事务和恢复测试。外部服务的副作用不会因为回放 checkpoint 自动撤销。

分步实现

  1. 给每个业务会话分配稳定且经过授权的 thread_id。
  2. 选择存储后端，配置迁移、加密、访问控制与备份。
  3. 从 checkpoint 恢复时识别哪些节点可能重跑，隔离有副作用的操作。
  4. 回放和 update_state 创建分支后保留父版本关联，避免误把旧分支当最新结果。

具体例子

报告已写入外部系统，但下一次 checkpoint 前进程崩溃。恢复后执行器不知道外部写入完成过，可能再次创建报告。这是两个系统之间的提交窗口。正确做法是使用稳定幂等键、查询写入结果，或使用事务 outbox 协调，不能靠“启用了 checkpointer”宣称 exactly-once。

代码与解释

# LangGraph 内存演示片段，不具备进程重启持久性
from langgraph.checkpoint.memory import InMemorySaver

app = builder.compile(checkpointer=InMemorySaver())
config = {"configurable": {"thread_id": "contract-42"}}
app.invoke(initial_state, config)
snapshot = app.get_state(config)
# 生产替换为合适的持久后端，并验证权限与恢复语义
  • Checkpointer 管任务状态，Store 管跨线程记忆，两者职责不同。
  • 不能让客户端猜一个 thread_id 就读取其他用户任务。
  • 回放下游可能再次消耗模型 token 或调用工具，应告知操作者影响。

常见误区

把内存存档称为生产持久化会在重启时丢任务。把节点重放理解为外部世界回滚，则可能重复付款或重复发信。

理解自测与验收

  • 在写入前、写入后、存档前分别注入崩溃。
  • 恢复后任务状态一致且外部写入不重复。
  • 用户 A 不能读取或恢复用户 B 的 thread。

15 · Interrupt：批准、拒绝与编辑后恢复

恢复会从节点开头重跑，所以中断前的代码可能再执行。

原理与边界

interrupt(payload) 把待决事项交还外部并保存执行状态。恢复时使用相同 thread_id 和 Command(resume=value)。它不是把 Python 调用栈冻结在某一行；包含中断的节点会重新开始执行，中断位置获得恢复值。因此中断前做外部写入非常危险，审批应与执行分离，并在执行前再次核对参数。

分步实现

  1. 把将要执行的动作、收件人、版本和摘要放进可序列化审批载荷。
  2. 节点调用 interrupt，外部界面显示真实参数并收集批准或拒绝。
  3. 同 thread 恢复，验证审批值并返回 approved 状态。
  4. 后续执行节点复核摘要与权限，使用幂等键执行一次业务动作。

具体例子

审批节点先打印“进入审核”再 interrupt。恢复后这条日志会再出现，是预期行为。如果同一位置改成发送邮件，就会重复发送。编辑后批准也不是随意信任前端返回的数据：修改后的参数要重新经过 schema、资源授权与内容校验，必要时再次审批。

代码与解释

# LangGraph 节点核心片段，配合 checkpointer 使用
from langgraph.types import interrupt, Command

def approve(state):
    decision = interrupt({"report": state["report"],
                          "version": state["version"]})
    return {"approved": decision is True}

# graph 中还应有根据 approved 路由的条件边
app.invoke(Command(resume=True), config)  # 与初次同 thread_id
  • 中断前避免副作用；不可避免时必须幂等。
  • 不要用宽泛 except 吞掉中断控制异常。
  • 多处 interrupt 的顺序影响恢复匹配，不应随意交换或条件跳过。

常见误区

用户点拒绝不应成为可自动重试的错误。审批结果若不绑定版本，等待期间内容改变就可能执行未经批准的新动作。

理解自测与验收

  • 拒绝后外部写入为零。
  • 恢复时节点进入次数增加，但发送次数仍为一。
  • 版本改变后原批准失效。
