02 · 拆开一次完整的 Agent Loop

用消息、工具调用 ID 和停止原因理解循环。

原理与边界

一次模型响应可能是文本，也可能包含一个或多个工具请求。宿主必须先保存模型响应，再执行获准的工具，把每个结果与原调用 ID 配对放回消息历史，然后再次请求模型。模型根据新观察继续决策。因此“循环”不是重复同一句提示，而是不断积累可验证观察。

分步实现

  1. 准备系统规则、当前用户目标、消息历史和允许的工具定义。
  2. 调用模型，先保存完整 assistant 响应，再读取结构化工具调用列表。
  3. 逐个校验工具名、参数、权限，执行并返回同一调用 ID 对应的成功或错误结果。
  4. 没有工具调用时进入业务验收；达到轮次、时间或费用限制时记录受限终止，不能标为成功。

具体例子

输入“查合同到期日”。模型输出 call_1: search({query:"到期日"})；宿主查到第 8 页并返回 call_1 的结果；模型引用该结果回答。若工具超时，反馈的是可识别的 timeout，不是伪造一条搜索结果。模型可选择缩小检索范围，但重试次数仍由运行时限制。

  • 必须保留 assistant 的调用消息，否则模型收到结果却找不到对应请求。
  • 错误也是观察，应区分超时、无权限、参数错误，不能全部转成“空结果”。
  • 参考项目 s02 用 for 顺序执行多个工具；同轮多个请求不等于并行。

常见误区

无工具调用只说明模型本轮想停止，不能证明测试通过或文件已经保存。若工具结果没有返回，不能先压缩掉调用记录再继续。

理解自测与验收

  • 每个工具结果有且只有一个有效调用 ID。
  • 持续请求工具的模型在预算耗尽时必定退出。
  • 工具失败能够回传错误，且不会被成功计数器统计。
